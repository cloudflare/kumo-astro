## Overview

<p>
  A Shiki-powered syntax highlighter for Astro. Supports 200+ languages with TextMate grammars and dual light/dark themes baked into every code block.
</p>

<p>
  Highlighting runs at build time in Astro's SSR frontmatter, so the colored HTML is shipped pre-rendered — no JavaScript is loaded in the browser for the highlighting itself, and no <code>client:</code> directive is needed.
</p>

</ComponentSection>

## Custom Highlight Color

The background color used by `highlightLines` is controlled by the `--kumo-code-highlight-bg` CSS custom property. Override it on the component (or any ancestor) to tint highlighted lines a different color.

<ComponentExample

  lang="astro"
>

  console.log(\`Hello, \${name}!\`);

}`} lang="typescript" highlightLines={[2]} class="[--kumo-code-highlight-bg:hsla(220,80%,50%,0.15)]" />

## Server-Side Rendering

`CodeHighlighted.astro` already runs at build time — Shiki is invoked in the component's frontmatter, so the highlighted HTML is baked into the page. There's no separate "server" API to call.

If you need to highlight code outside of a component (e.g. in a custom Astro endpoint or a build script), use the same `highlightCode()` helper directly:

```astro
---
import { highlightCode } from "@cloudflare/kumo/code/server";

const html = await highlightCode(`const x = 1;`, "typescript");
---

<div class="kumo-shiki" set:html={html} />
```

</ComponentSection>

## Migration from `Code`

The earlier `Code.astro` component (exported from `@cloudflare/kumo-astro/components/code`) only supported `code`, `lang`, `showCopyButton`, and `class`. `CodeHighlighted` is a drop-in superset of that API — same defaults, same rendered output, plus `showLineNumbers`, `highlightLines`, and `labels`.

```astro
{/* Before */}
import Code from "@cloudflare/kumo-astro/components/code";
<Code code="const x = 1;" lang="typescript" />

{/* After */}
import CodeHighlighted from "@cloudflare/kumo-astro/components/code-highlighted";
<CodeHighlighted code="const x = 1;" lang="typescript" />
```

</ComponentSection>
